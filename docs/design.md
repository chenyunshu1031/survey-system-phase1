# 第一阶段系统与数据库设计

## 系统边界

登录用户创建问卷，只能列出和读取自己拥有的问卷。草稿问卷可编辑标题、说明、匿名和重复填写设置、截止时间，并添加或修改四种题型及条件跳转。题目按问卷内的 `order` 排列；编辑题目不会改变顺序，未删除选项的 ID 会保留。发布后，已登录用户可通过 `/survey/{slug}` 逐题填写并提交；已截止或关闭的链接仅展示问卷内容和状态。

填写者必须登录；匿名提交在统计中隐藏身份，服务端保存账户标识以执行重复填写限制。问卷默认不允许重复填写，创建者可开启。跳转规则保存在题目数据中，按优先级匹配，未命中则到下一题；只允许向后跳，跳过题目无需作答。发布后锁定题目结构、匿名和重复填写设置，标题、说明、截止时间仍可修改。未提交答案仅暂存于当前页面。创建者可查看统计，匿名答卷的展示身份为“匿名”。

## MongoDB 集合

| 集合 | 核心字段 | 用途 |
| --- | --- | --- |
| `users` | `username`, `usernameKey`, `passwordHash`, `createdAt`, `schemaVersion` | 大小写不敏感的账号标识；密码仅存 Argon2 哈希。 |
| `surveys` | `ownerId`, `slug`, `title`, `description`, `allowAnonymous`, `allowMultipleSubmissions`, `status`, `deadlineAt`, `configurationRevision`, `submissionRevision`, 活动操作计数, 时间戳, `schemaVersion` | 问卷配置和生命周期。`slug` 用于分享；活动计数协调状态切换；配置版本检查编辑冲突，提交版本检查统计分页一致性。 |
| `questions` | `surveyId`, `order`, `type`, `title`, `required`, `options`, `validation`, `jumpRules`, `schemaVersion` | 独立题目集合；选择题选项有稳定 ID，跳转目标引用题目 ID。 |
| `responses` | `surveyId`, `respondentId`, `isAnonymous`, `answers`, `visitedQuestionIds`, `submittedAt`, `singleSubmission`, `schemaVersion` | 已提交答卷；仅保存实际作答内容，另记访问路径；账户 ID 用于重复填写约束。 |

启动时用 MongoDB `$jsonSchema` 校验基础类型，并建立唯一和查询索引：用户名键、问卷 `slug`、问卷内题目顺序；按创建者列问卷。`responses` 上的部分唯一索引用于“不允许重复填写”的并发约束。

嵌套校验覆盖 `validation` 的已知字段类型、`jumpRules` 的规则对象结构、`answers` 中标量或字符串选项数组，以及非空、不重复的访问路径。题型与字段是否对应、规则引用是否有效、选项 ID 是否重复等业务约束仍由后端检查。答卷查询按 `(submittedAt 降序, _id 降序)` 稳定排序，使用 `responses(surveyId 升序, submittedAt 降序, _id 降序)` 索引，避免只按两列建索引时额外执行排序。初始化先建立新索引，再替换本项目旧的两列非唯一索引；不删除答卷数据。

## 关键逻辑

注册时对用户名去首尾空格并生成 `casefold()` 检索键；先查重，写入时再由唯一索引兜底。登录时验证 Argon2 哈希，JWT 的 `sub` 保存用户 ID，`exp` 保存过期时间；后端要求两者存在，验证签名、过期时间和账号标识。读取问卷时按 `_id` 与 `ownerId` 核实归属；读取或修改题目前先核实所属问卷，再按 `surveyId` 查询题目，其他用户得到 404。添加题目时在题目集合内取最大顺序加一，并由唯一索引防并发重号；发生冲突时有限次重试。题目请求模型校验题型与规则对应关系、选项重复、最小/最大范围。发布前再次检查题目配置，防止旧数据中已不合法的设置被直接发布。

登录令牌在前端统一维护：401 只清除该请求对应的当前会话，旧请求不能清除后来建立的新会话。临时网络失败不作为登录失效处理；旧账号的个人信息请求也不能覆盖新账号。管理页和填写页的路径参数改变时重新加载对应页面，避免继续使用上一份问卷的数据。

### 条件跳转

- 单选：选中指定选项时跳转；多选：答案包含指定选项中的任意一个或全部时跳转；数字：等于、大于、大于等于、小于、小于等于或落在闭区间时跳转。文本题不配置条件跳转。
- 同一题的规则按唯一 `priority` 从小到大检查，第一条命中即生效；均未命中时进入顺序中的下一题。界面通过上移、下移调整优先级。
- 目标只能是本问卷中 `order` 更大的题目；规则引用稳定的题目 ID 和选项 ID。修改题型、选项或校验限制会清空该题已有规则，创建者需要重新配置。
- 单条条件与题目限制相矛盾时拒绝保存，例如 0–100 的数字题配置“大于 200”，整数题要求“等于 1.5”，最多选一项的多选题要求同时包含两项。允许有意重叠的规则按优先级执行；创建者界面显示重叠或完全覆盖提示，刷新后按保存规则重新计算。数字使用区间分析，多选使用选项集合、数量约束及有上限的搜索；复杂组合未分析完时明确提示试填，避免保存操作无界计算。
- 前端按规则展示下一题；提交时服务端独立复算完整路径，不能通过篡改请求跳过本该作答的题。

### 生命周期和访问

持久化状态为 `draft → published → closed`。已发布问卷若超过 `deadlineAt`，返回给前端的派生可用状态 `availability` 为 `expired`；关闭时为 `closed`，未截止时为 `open`。发布要求至少一道题、截止时间仍在未来，并再次检查所有跳转规则。发布后题目与跳转规则、匿名和重复填写设置锁定；标题、说明和未来截止时间可更新。关闭后不能再次发布。公开 API 以 `slug` 读取已发布或已关闭问卷，要求登录，不返回创建者 ID；提交接口在写入时再次检查发布和截止状态。

发布使用严格模式复核已存题目和规则，不通过隐式类型转换把异常旧配置当作合法数据；同时检查选项标识是否有效且不重复、规则是否保留标识。无效配置返回 409 并保留草稿，创建者修复后再发布。保存规则允许清除旧的缺失标识规则，防止异常旧配置无法修复。发布最终更新条件也使用检查结束后的当前时间筛选截止时间，避免只在检查开始时判断。

题目写入前，服务端在 `surveys` 文档中原子增加 `activeQuestionMutations`，完成后释放；发布只在该计数为零时生效。答卷提交同样先核对开放状态和截止时间，并原子增加 `activeSubmissions`；关闭只在该计数为零时生效。操作异常时通过 `finally` 释放计数；单进程服务意外中断后，启动初始化会将残留计数清零。第一阶段按单服务进程运行；若扩展为多个服务实例，应改为支持副本集事务或跨实例租约的设计。

仅检查活动计数不能识别“其他编辑在读取后已经完成”的情况。因此题目写入预占还要求当前没有其他配置写入，并比较、递增 `configurationRevision`；设置更新也原子比较并递增此字段。发布最终写入时，必须与开始检查时的配置版本相同，避免在旧快照上发布。冲突返回 409，用户刷新后重试。缺少该新增字段的旧文档按版本 0 处理，不需要删除旧数据。它是内部编辑并发版本，与 `schemaVersion` 的数据结构版本含义不同；目前没有实现浏览器长期打开旧表单时的客户端版本锁。

### 答卷校验与保存

前端按题目类型输入单选选项 ID、多选选项 ID 数组、文本或数字。提交请求按访问顺序携带每道到达题目的 `questionId` 和答案；未回答的选答题使用 `null`，多选也可使用空数组。服务端从第一题开始逐题检查题型、必答、选项、数量、字数、数值及整数限制，并用保存的跳转规则推导下一题；路径不完整、顺序错误或插入了被跳过的题均拒绝。只有实际回答的值写入 `answers`，完整访问顺序写入 `visitedQuestionIds`。未允许匿名的问卷拒绝匿名请求；匿名答卷仍保留 `respondentId`，后续展示结果时须隐藏其身份。禁止重复填写时，写入前查询并由唯一索引防止并发重复提交。

数字答案使用有限浮点数，绝对值不超过 9,007,199,254,740,991；该范围用于保持前后端数字处理边界一致，并不保证所有十进制小数精确表示。创建、修改和发布时，数字限制必须与可处理范围有交集；整数题的范围还必须包含整数。文本长度按 Unicode 码点计数，表情组合并不一定等于一个码点。日期输入检查真实日历日期，拒绝将不存在的日期自动转到次月。

文本答案在前后端使用相同的首尾空白字符集合（含全角空格、NEL、控制分隔符与 BOM），归一化后再检查必答和长度。空数组只表示多选留空，不能作为其他题型的合法空值；多选也不能用空字符串代替选项数组。配置中的计数和优先级须处于安全整数范围，避免 JSON/BSON 转换溢出。MongoDB 单份 BSON 文档有大小上限；写入过大内容返回 413 和明确提示，失败提交会释放活动计数，不保存半份答卷。

## 统计与数据兼容

统计按 `surveyId` 分批读取已提交答卷并实时计算，不另外保存可能过期的汇总值。`visitedQuestionIds` 用于区分跳过与到达但留空，`answers` 用于统计有效回答；多选按选项分别计数。文本和数字保留原始填写内容，统计接口按快照时间每次最多返回 100 条原始内容，前端可逐页加载全部内容；数字平均值始终基于全部有效数字。非匿名答卷展示用户名，匿名答卷从统计响应中隐藏账户标识。

`asOf` 是时间筛选上界，不是数据库事务快照。每次接受提交预占时递增 `submissionRevision`（即使该次最终校验失败也不回退）。统计开始和结束都检查此版本及活动提交计数；分页继续携带首次的 `asOf` 与 `submissionRevision`。处理中或版本变化时返回 409，要求刷新，避免延迟写入或毫秒时间精度使前后页不一致。刷新后的统计也不会再拼接刷新前尚未完成的分页结果。缺少提交版本的旧文档按 0 处理；直接绕过应用写库或数据迁移不受该机制保护。

数字平均值采用补偿求和后除以有效回答数，减少较大正负值抵消时丢失小值的误差；计算仍使用浮点数，不作为任意精度十进制计算。

MongoDB `$jsonSchema` 检查文档结构和字段类型，题型语义及跨集合引用由请求模型和服务层校验。`schemaVersion` 标识数据结构版本，第一阶段为版本 1。缺少内部操作版本的旧问卷按 0 读取；异常旧配置通过发布复核识别，并由合法编辑接口修复。

服务采用单进程操作计数及启动恢复机制。结构扩展需要同时调整集合校验、后端处理和前端界面，并保留旧数据读取或迁移规则；多实例部署还需采用跨实例协调方案。
