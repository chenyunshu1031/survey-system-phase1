## 三、技术与设计要求核对

| 实验要求 | 对应实现或说明 |
| --- | --- |
| MongoDB 为后端数据库，业务数据保存在 MongoDB | users、surveys、questions、responses 四集合；业务读写使用 PyMongo。mongomock 仅用于隔离自动测试，未作为业务数据库 |
| 不使用关系数据库或现成问卷系统框架 | 后端采用 FastAPI/Pydantic/PyMongo，前端采用 Vue 3/TypeScript/Vite；问卷业务由项目代码实现 |
| 不将所有数据放在一个集合 | 四集合按修改方式与增长特点划分；题目和答卷独立增长 |
| 谨慎冗余 | 设计文档解释 usernameKey、singleSubmission、visitedQuestionIds 的用途与生成方式；统计不另存汇总 |
| 具体业务逻辑不针对单份问卷写死 | 每题选项、validation、jumpRules 保存在数据中；程序定义通用题型和操作符 |
| 说明设计原因、与关系结构的取舍及 MongoDB 适用性 | 报告第三章与 design.md 说明嵌入、引用、单文档提交、索引，以及跨集合约束由后端维护的代价 |
| 第一阶段成果可作为后续修改基础 | 保留源代码、原始答卷、访问路径和 schemaVersion；当前未实施第二阶段迁移 |
