测试对象：基于 MongoDB 的在线问卷系统第一阶段实现。

## 一、测试范围与方法

测试围绕创建问卷、添加题目、条件跳转、输入校验、答卷提交和结果统计展开。除正常流程外，还检查账号隔离、匿名展示、重复填写、截止与关闭、并发提交及存储边界。各用例记录操作步骤、输入数据、预期输出、实际输出和执行结果。

| 方式 | 实施方法 | 验证内容 |
| --- | --- | --- |
| 自动化 API 测试 | pytest、FastAPI TestClient，检查状态码、响应和数据库 | 业务接口及错误处理 |
| 服务逻辑测试 | 直接调用校验、跳转解析和规则分析函数 | 边界及组合条件 |
| 真实 MongoDB 集成 | 独立数据库中检查集合、索引及接口读写 | 真实约束、并发、文档上限 |
| 前端自动测试 | Node 测试工具检查会话、时间及答案处理 | 前端逻辑 |

后端以自动化 API 测试为主，检查接口响应和保存的数据；集合约束与并发写入使用真实 MongoDB 验证。前端逻辑通过自动测试检查，页面操作另作手工验收。测试环境按单个后端进程运行。

## 二、环境、数据与执行方法

### 2.1 约定

- 安装及启动方法见 [README](../README.md)：Python 3.12+、符合项目 Vite 要求的 Node.js、MongoDB 7/8。
- 常规测试使用 mongomock 隔离数据，各用例独立准备账号和问卷。
- 最近一次真实库验证使用独立 MongoDB 8.3.11、27018 端口；测试库名为随机 `survey_system_test_*`，结束后清理，不操作日常问卷。
- 下文省略 `/api/v1` 前缀。登录后使用 `Authorization: Bearer <accessToken>`。
- 问卷、题目、选项 ID 和 slug 取自实际响应；A/B/X/Y 等为选项文字，实际答案使用对应 ID。
- 自动测试的实际输出依据接口响应及数据库断言记录。
- T01—T22 为业务用例编号，一个用例可对应多个测试函数或参数化执行项。

### 2.2 自动执行

依照 README 准备后端虚拟环境，在 `backend` 目录执行：

```powershell

```

普通运行不启用真实库测试。确认独立 MongoDB 可连接后，在同一测试终端执行（端口按实际调整）：

### T08 不可命中条件与警告

测试步骤：

1. 草稿中创建整数题 0～100 及两道后续文本题。
2. 保存“≥50 跳第三题”，保留接口返回的规则。
3. 用“>200”替换，检查错误响应，再读取原规则。
4. 保存优先级 1“≥50 跳第三题”、优先级 2“≥25 跳第二题”，读取检查警告。
5. 检查数据库是否保存警告字段；发布后读取填写接口，检查是否对填写者返回警告。

输入：`PUT /surveys/{id}/questions/{qid}/jump-rules`；分别为 `gte 50`、`gt 200`、按顺序的 `gte 50/gte 25`，目标为本问卷后续题。

预期输出：不可命中配置 422，原规则不变；重叠配置 200 且有警告；数据库和填写接口不含 `jumpRuleWarnings`。

实际输出：返回 422，提示包含“永远无法命中”，原规则一致；重叠配置返回 200 和“条件重叠”提示；警告字段范围检查通过。

结果：通过。

代码：[test_jump_analysis.py](../backend/tests/test_jump_analysis.py)，`test_rule_api_rejects_impossible_input_without_overwriting_and_returns_warnings`。

### T12 文本、类型及数字边界

测试步骤：

1. 对文本答案添加特殊首尾空白，前后端分别执行归一化和长度检查；长度恰为 1 时输入普通单码点表情。
2. 对单选、文本、数字传空数组，对多选传空字符串，检查校验结果。
3. 创建数字题，提交支持范围的合法端点。
